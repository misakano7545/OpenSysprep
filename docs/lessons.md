# 经验与踩坑

> 惯例：现象 → 结论/做法；按主题归并，新增条目写进对应主题。只记可复用教训，不记流水账。

## 逆向分析

- ASPack 把整个资源区压成一条流；重建 PE 时**资源目录基准必须取数据目录表里的 RVA**（≠ `.rsrc` 节地址），偏移算错会解析出魔数（如 `#1769554670`）。
- `file` 命令对 UPX 变种识别不可靠：直接 `upx -d` 试解，失败再判定未加壳。
- Delphi 程序字符串 ASCII / UTF-16 混排：检索必须双编码并行，单编码会漏掉一半证据。
- 组件嵌套：`FUNN` 内嵌 `FUNA/FUNB/FUNC` 二级 PE（`FUNB` 即浏览器配置组件所在）；定位证据要按「文件 → 资源 → 内嵌组件」逐层落点。
- 短标识符（如 `we2`）命中随机字节会误报；必须看上下文字符串再下结论。
- ASPack 会把**尾部资源**（图标 / 版本信息 / 清单）以**原样字节**存放在 `.aspack` 段的地址范围内：重建时不能丢弃壳区字节，且 `.rsrc` 的 VirtualSize 必须延伸到 `.adata` 起点，否则资源表里这些条目会指向文件外（`OUT!`）。
- PE 重建时 `SizeOfOptionalHeader` 在 **COFF 头**（`e_lfanew+20`），不是 OptionalHeader 的 Magic 字段；取错会让节表整体偏移 0x2B，产物节表报废（资源仍可按 RVA 直读，但外部工具解析不了）。
- `VS_VERSIONINFO` 解析：按 NUL 切分后**键名会粘上前一字段尾部字节**（String 结构 = wLength/wValueLength/wType + szKey，如 `L\x16\x01CompanyName`）。必须用**后缀匹配**；用精确 `in KEYS` 会得到恒空表，而且不报错——最隐蔽的一类"分析结论为空"。
- 判断「资源损坏是样本自带还是自己导出坏」：① 同批相邻资源（字符串表 / 邻接模块）是否完好；② 从**原包**独立重脱壳后比对 sha256。两者都指向厂商侧，才能下"样本自带损坏"的结论。
- 文本化损坏模型（本样本）：`0x00 → 0x20`（空格）+ GBK 非法双字节对折叠成 `0x3F`；用**标准 DOS stub 逐字节反推**可验证模型（`0E 1F BA 0E 00 B4 09 CD 21 B8 01 4C CD 21` → `0E 1F 3F 20 3F 3F 3F 4C 3F`）。这类损坏下 `e_lfanew`/节表数值字段不可逆丢失。
- 关键词命中要分类核实：「伪装」类命中会撞上**签名证书链**（WoSign / Microsoft Time-Stamp PCA）；先分清"服务名/版本信息伪装"与"只是带签名"，再写结论。
- 模块身份优先看**版本信息资源**（CompanyName/InternalName/OriginalFilename + PE 时间戳），比字符串关键词更硬；同一家族的时间戳能直接分出两条发行线（如 2026-05 正式线 vs 2025-05 KR 线）。
- 判「无导入表载荷」：整文件搜 `*.dll` 名（ASCII 名在损坏下会存活，PUBCI 的 `AUTHZ.dll` 即证）+ 搜 `65 48 8B 04 25 60 00 00 00`（`mov rax, gs:[0x60]`，PEB）。两者同时成立 ⇒ 依赖自解析 API 的载荷/存根，而不是常规 EXE。
- 文本化损坏下**代码惯用法仍可反查**：先用损坏模型把字节还原（`0x20→0x00`、`0x3F` 还原为被吃掉的 2 字节），再比对已知指令编码；例：`65 48 3F 25 60 20 20 20` ↔ `65 48 8B 04 25 60 00 00 00`。
- 模块名不落地（主程序搜不到 `FUNN`/`PUBCH`）时，别死磕字符串：**看资源顺序 + 加密配置**（本样本的配置加密是付费功能线，见更新日志），并接受"名字→用途"映射不可得。
- 分包里的**更新日志/公告**是廉价高价值的旁证（功能溯源、版本线、哪些功能仅付费封装方式可用）——先解包拿到它，再下"这机制属于哪条线"的结论。
- `objdump -D -j .text` 对 5.6 MB 代码段全量反汇编只要 24 s、字节覆盖 99.94%，**是零成本拿到"完整反汇编"的路子**（不需要切镜像、不需要装 Ghidra）；直接 `call/jmp` 解析成绝对地址 ⇒ 可以顺着调用图人工走。
- 但线性扫描**分不清 `.text` 里的数据**：Delphi 把 RTTI/resourcestring/窗体表放进 `.text`，1.43% 会显式 `(bad)`，另有一部分数据被当成指令 ⇒ 指令级计数不可全信；读语义仍需递归下降反汇编器。
- Delphi 程序**别指望按 API 名 grep 调用点**：API 名只以字符串存在于 `.idata`，代码通过运行期解析的指针表调用（`ds:0x…`），PE 导入表本身可能还是壳残留；真要 API 级导航得上 IDR（Windows）或做 Delphi 导入表解析。

## 工程 / CI

- `dtolnay/rust-toolchain@stable` 一次装好 components + targets；Linux 上 `cargo check --target x86_64-pc-windows-msvc` 无需链接即可对 Windows 代码做类型检查——把 Windows 相关代码错误提前到 Linux CI 阶段。
- 把产品红线做成 CI 步骤（禁止标识 grep），约束才真正"可执行"，不然只是文档口号。
- 分析素材及时归档到 `work/`（本机、不入库）；临时目录会被系统清理。
